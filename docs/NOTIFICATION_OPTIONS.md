# FeedWatch 알림 방식 검토

## 적용한 기본 조합

FeedWatch는 **이메일 + 웹 푸시 알림**을 함께 사용한다.

- 이메일은 브라우저가 꺼져 있어도 기록이 남는 기본 채널이다.
- 웹 푸시는 Android, PC, iPhone/iPad의 홈 화면 웹 앱에서 새 글을 즉시 팝업으로 보여준다.
- 사용자별 `알림 받을 사이트` 설정은 이메일과 웹 푸시에 동일하게 적용된다.
- 크롤러는 매시간 실행되며, 새 글이 있을 때만 알림을 보낸다.

## 기기별 동작

| 환경 | 웹 푸시 | 사용 조건 |
|---|---|---|
| Android Chrome/Edge | 지원 | HTTPS 접속 후 프로필에서 알림 허용 |
| Windows/macOS Chrome/Edge | 지원 | 브라우저 알림 허용 |
| macOS Safari | 지원 | 사이트 알림 허용 |
| iPhone/iPad | 지원 | iOS/iPadOS 16.4 이상, Safari에서 `홈 화면에 추가` 후 홈 화면 아이콘으로 실행 |

브라우저의 알림 권한을 거절한 경우에는 운영체제 또는 브라우저 설정에서 FeedWatch 권한을 다시 허용해야 한다.

## 운영자가 최초 1회 설정할 항목

1. Firebase Console의 Cloud Messaging에서 Web Push 인증서(VAPID 공개키)를 생성한다.
2. `web/firebase_config.json` 또는 GitHub 변수 `FIREBASE_WEB_CONFIG`에 `vapidKey`를 추가한다.
3. 배포 후 사용자마다 프로필에서 `이 기기에서 모바일·PC 팝업 알림 받기`를 켠다.
4. GitHub Actions Secrets에 `FIREBASE_SERVICE_ACCOUNT`가 등록되어 있어야 한다.
5. 사용자 문서의 `notify_push`, `push_fids`가 저장되는지 관리자 진단 화면에서 확인한다.

VAPID **공개키**는 웹 설정에 들어가도 되는 값이다. 서비스 계정 JSON이나 개인키는 절대 웹 파일에 넣지 않는다.

## 검토했지만 기본 채널로 채택하지 않은 방법

### 카카오톡

카카오 메시지 API는 일반적인 서버 발송형 알림 서비스가 아니다. 사용자 로그인·동의, 친구 관계 또는 별도 비즈니스 권한, 쿼터 등 제약이 있어 FeedWatch의 기본 알림으로 쓰기 어렵다.

### 문자(SMS)

도달률은 높지만 건당 비용, 발신번호 등록, 개인정보 관리가 추가된다. 웹 푸시와 이메일이 모두 실패했을 때 필요한 핵심 사용자에게만 선택적으로 도입하는 편이 적합하다.

### Slack·Teams·Discord

팀 단위 운영에는 유용하다. 향후 웹훅 URL을 관리자 설정에 추가해 한 채널로 요약 알림을 보내는 확장안이 가능하지만, 개인 모바일 알림의 기본 수단으로는 웹 푸시가 더 간단하다.

## 장애 시 확인 순서

1. 최근 크롤링 이력에 `[NOTIFICATION]` 오류가 있는지 확인한다.
2. GitHub Actions 크롤러 실행이 매시간 성공하는지 확인한다.
3. 관리자의 시스템 진단에서 푸시 등록 기기 수를 확인한다.
4. 사용자의 프로필에서 이메일·팝업 알림과 대상 사이트가 켜져 있는지 확인한다.
5. 기기의 알림 설정에서 브라우저 또는 홈 화면 FeedWatch 알림이 허용되어 있는지 확인한다.
